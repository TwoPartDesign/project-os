# Project OS v3.0 — "Lean Context" (proposed feature set)

Synthesis of the Claude Code 2.1.270–2.1.289 audit and the ICM paper review
(`docs/audits/2026-10-03-changelog-alignment.md`). Shorthand; task IDs point at
ROADMAP `Feature: changelog-alignment-2026-10` (and #T202–#T204 from 2026-09).
`[ ]` = approved, `[?]` = draft awaiting /pm:approve.

**Theme:** load less, trust native features, and make every gate fail loudly.
v2 built the governance; v3 makes it cheaper to run and harder to fool.

## 1. Context that is actually scoped (headline)
- Path-scoped rules work (`globs:` → `paths:`) — tests/api rules stop loading everywhere `[ ]` #T205
- Workers get one clean context: no lead-only instructions, no double-pasted conventions `[ ]` #T207 → #T208
- Design reads only the ADRs it needs, plus an ADR-conflict check `[?]` #T220
- Always-loaded budget (2,500 tokens) enforced by a deterministic check `[?]` #T221
- **Target:** worker baseline ~35 KB → <10 KB; design run ~30k → <10k tokens
